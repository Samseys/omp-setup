Comments: Maximum 2 lines. Comments must explain why, constraints, assumptions, or non-obvious behavior. Never restate what the code does.

No historical comments: Do not document how, when, or why the code changed. Do not mention previous implementations, migrations, bugs that were fixed, or historical decisions. Git provides history.

Documentation: Keep relevant documentation up to date when behavior, interfaces, configuration, workflows, or user-facing functionality changes.

Prefer code clarity over comments. If a comment is needed to explain complicated code, first consider whether the code can be simplified or renamed to make the intent obvious.
